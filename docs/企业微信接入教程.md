# 企业微信接入教程

本文适用于企业内部自建应用。员工从企业微信工作台打开移动端 H5，或从普通浏览器扫码进入桌面工作台。企业微信负责确认员工身份，业务工作台根据已有账号决定是否允许登录，并继续使用 `biz_sid` 会话、账号权限和强制改密流程。

示例使用单个企业、单个自建应用和管理员预绑定。建议先跑通企业微信客户端内的登录，再按需增加浏览器扫码、消息通知和事件回调。现有普通微信小程序的扫码绑定使用自己的凭证和身份命名空间。

## 1. 创建自建应用并配置域名

1. 进入[企业微信管理后台](https://work.weixin.qq.com/)，打开「应用管理」，创建自建应用。先把可见范围设为一组测试人员。
2. 在「我的企业」记录企业 ID（CorpID），在应用详情记录 AgentID 和 Secret。Secret 仅由后端读取。
3. 在应用的网页授权或开发配置中，把 `biz.example.com` 配成可信域名。若后台要求验证域名归属，按页面提示将校验文件放到指定位置，确认通过 HTTPS 可以读取该文件。
4. 将应用主页设为 `https://biz.example.com/api/wecom/authorize`。把 `https://biz.example.com/api/wecom/callback` 作为代码里的 OAuth 回调地址，确保主机名和可信域名一致。
5. 若应用后台要求配置「企业可信 IP」，填运行 Egg 的服务器访问企业微信时所用的公网出口 IP。服务器经过 NAT 或代理时，使用实际出口 IP。
6. 需要桌面网页扫码时，确认该自建应用的 OAuth 可信域名或 Web 网页授权回调域名覆盖相同的回调主机。

本项目的 [Nginx 模板](../deploy/nginx/business-workbench.conf) 已把 `/api/` 转发给 Egg，示例站点监听 HTTP。联调环境需要配置 HTTPS，并让浏览器请求和授权回调使用同一个域名，保留 `Host`、`X-Forwarded-Proto` 转发。入口和回调均由 Egg 处理，无需新增 Umi 路由。部署方式见[部署说明](../deploy/deployment.md)。

官方文档：[构造网页授权链接](https://developer.work.weixin.qq.com/document/path/91022) · [Web 登录组件](https://developer.work.weixin.qq.com/document/path/98152)

## 2. 配置后端和预绑定账号

在 `backend/.env` 或部署环境中设置以下值。同步在 [backend/.env.example](../backend/.env.example) 增加空值示例。生产环境的 `APP_KEYS` 使用独立随机值，同一部署的所有进程使用相同值，以便校验授权状态 Cookie。

```dotenv
WECOM_CORP_ID=wwxxxxxxxxxxxxxxxx
WECOM_AGENT_ID=1000002
WECOM_SECRET=替换成自建应用的Secret
WECOM_REDIRECT_URI=https://biz.example.com/api/wecom/callback
```

在 [config.default.ts](../backend/config/config.default.ts) 的 `bizConfig` 中增加配置，并在 [typings/index.d.ts](../backend/typings/index.d.ts) 的 `EggAppConfig` 声明同形状的 `wecom` 对象，四个属性均为 `string`。

```ts
wecom: {
  corpId: (process.env.WECOM_CORP_ID || '').trim(),
  agentId: (process.env.WECOM_AGENT_ID || '').trim(),
  secret: (process.env.WECOM_SECRET || '').trim(),
  redirectUri: (process.env.WECOM_REDIRECT_URI || '').trim(),
},
```

身份绑定复用现有的 [user_identities 迁移](../backend/database/migrations/20261124000100_create_user_identities.ts)。将 `provider` 设为 `wecom`，在现有 `app_id` 列保存 CorpID，在 `openid` 列保存企业微信返回的 `userid`。这两个列名沿用现有表结构，组合键 `(provider, app_id, openid)` 表示某企业的一个成员身份。登录时使用 `users.id` 加载工作台账号。

先在工作台创建启用的测试账号，再从企业微信管理后台通讯录确认成员账号（UserID）。账号名称、手机号和显示姓名可能和工作台信息不同，绑定时逐一核对实际 UserID。运行迁移后，通过有权限访问实例数据库的运维人员执行如下示例。把 CorpID、UserID 和本地账号替换为测试值。

```bash
cd backend
npm run migrate
```

```sql
INSERT INTO user_identities
  (user_id, provider, app_id, openid, status, created_at, updated_at)
SELECT id, 'wecom', 'wwxxxxxxxxxxxxxxxx', 'zhangsan', 1,
       CURRENT_TIMESTAMP, CURRENT_TIMESTAMP
FROM users
WHERE username = 'wecom-test' AND status = 1;
```

确认影响行数为 1。重复绑定触发唯一约束时，先检查原绑定归属。需要调整绑定时，关闭旧绑定或在管理员确认后修改归属。若要求解除绑定后现有会话立即失效，在同一个数据库事务内撤销该本地账号的会话。当前 `sessions` 表没有登录来源字段，这样会同时退出该账号在其他设备和登录方式建立的会话。

## 3. 实现两种授权入口

在 [backend/app/router.ts](../backend/app/router.ts) 注册入口和 OAuth 回调。这三个 GET 路由在建立会话之前运行。现有 [origin-guard.ts](../backend/app/middleware/origin-guard.ts) 会放行 GET，因此回调中的 `state` 校验负责把响应绑定到发起授权的浏览器。

```ts
router.get('/api/wecom/authorize', controller.wecom.authorize);
router.get('/api/wecom/scan', controller.wecom.scan);
router.get('/api/wecom/callback', controller.wecom.callback);
```

在 `backend/app/controller/wecom.ts` 增加控制器。两个入口共用回调，通过签名 Cookie 保存随机 `state`、过期时间和固定的落地页。用户每次发起授权时覆盖旧状态。

```ts
import crypto from 'crypto';
import { Controller } from 'egg';
import { validationError } from '../lib/errors';

const COOKIE = '__Host-wecom_state';
const STATE_TTL = 5 * 60 * 1000;
const cookieOptions = {
  signed: true,
  httpOnly: true,
  sameSite: 'lax' as const,
  secure: true,
  overwrite: true,
  path: '/',
};

export default class WecomController extends Controller {
  public async authorize() {
    this.start('h5');
  }

  public async scan() {
    this.start('desktop');
  }

  private start(mode: 'h5' | 'desktop') {
    const { ctx } = this;
    const { corpId, agentId, redirectUri } =
      ctx.service.wecom.getConfig();
    const state = crypto.randomBytes(24).toString('hex');
    const expiresAt = Date.now() + STATE_TTL;
    ctx.cookies.set(COOKIE, `${state}.${expiresAt}.${mode}`, {
      ...cookieOptions,
      maxAge: STATE_TTL,
    });

    const url = new URL(mode === 'h5'
      ? 'https://open.weixin.qq.com/connect/oauth2/authorize'
      : 'https://login.work.weixin.qq.com/wwlogin/sso/login');

    url.searchParams.set('appid', corpId);
    url.searchParams.set('agentid', agentId);
    url.searchParams.set('redirect_uri', redirectUri);
    url.searchParams.set('state', state);
    if (mode === 'h5') {
      url.searchParams.set('response_type', 'code');
      url.searchParams.set('scope', 'snsapi_base');
      url.hash = 'wechat_redirect';
    } else {
      url.searchParams.set('login_type', 'CorpApp');
    }

    ctx.set('Cache-Control', 'no-store');
    ctx.redirect(url.toString());
  }

  public async callback() {
    const { ctx } = this;
    ctx.set('Cache-Control', 'no-store');
    ctx.set('Referrer-Policy', 'no-referrer');

    const { code, state } = ctx.query;
    const cookie = ctx.cookies.get(COOKIE, { signed: true }) || '';
    const [expectedState, expiresAt, mode] = cookie.split('.');
    if (
      !expectedState || state !== expectedState ||
      !(Number(expiresAt) > Date.now())
    ) {
      throw validationError('企业微信登录已失效，请重新发起');
    }

    ctx.cookies.set(COOKIE, null, cookieOptions);
    if (typeof code !== 'string' || !code) {
      throw validationError('未收到企业微信授权凭证，请重新登录');
    }

    await ctx.service.wecom.login(code);
    ctx.redirect(mode === 'h5' ? '/m/home' : '/welcome');
  }
}
```

两个入口均通过 `code` 和 `state` 回到同一个回调地址。`URLSearchParams` 会编码 `redirect_uri`，直接传入原始地址即可。企业微信的 `code` 只能使用一次，5 分钟内未使用会过期。授权失败或过期时，从登录入口重新发起。示例沿用项目的 JSON 错误响应，接入时可在浏览器流程中增加带重试入口的错误页。

官方文档：[构造网页授权链接](https://developer.work.weixin.qq.com/document/path/91022) · [获取访问用户身份](https://developer.work.weixin.qq.com/document/path/91023) · [Web 登录组件](https://developer.work.weixin.qq.com/document/path/98152) · [获取用户登录身份](https://developer.work.weixin.qq.com/document/path/98176)

## 4. 换取身份并复用现有会话

在 `backend/app/service/wecom.ts` 中使用 Node.js 自带的 `fetch` 调用企业微信。身份接口响应中的成员字段为小写 `userid`。首期只接受本企业成员，收到 `openid` 或带企业前缀的互联成员 ID 时拒绝创建会话。企业微信身份接口可能对应用可见范围外的企业成员也返回身份，工作台登录仍须通过自己的绑定和账号状态检查。

```ts
import { Service } from 'egg';
import { setSessionCookie } from '../lib/auth-cookie';
import { ApiError, deny } from '../lib/errors';
import { sqlNow } from '../lib/time';

const unavailable = () =>
  new ApiError(503, 'WECOM_UNAVAILABLE', '企业微信登录暂不可用');

let tokenCache: { token: string; expiresAt: number } | undefined;

interface WecomResponse {
  errcode: number;
  access_token?: string;
  expires_in?: number;
  userid?: string;
}

export default class WecomService extends Service {
  public getConfig() {
    const config = this.app.config.wecom;
    if (!config.corpId || !config.agentId || !config.secret ||
        !config.redirectUri) {
      throw unavailable();
    }
    return config;
  }

  private async request(path: string, params: Record<string, string>) {
    const url = new URL(path, 'https://qyapi.weixin.qq.com');
    url.search = new URLSearchParams(params).toString();

    try {
      const response = await fetch(url, {
        signal: AbortSignal.timeout(8000),
      });
      if (!response.ok) throw unavailable();
      return (await response.json()) as WecomResponse;
    } catch {
      // 请求地址可能包含凭证，日志仅记录接口路径。
      this.ctx.logger.warn('[wecom] request failed: %s', path);
      throw unavailable();
    }
  }

  private async accessToken(): Promise<string> {
    if (tokenCache && Date.now() < tokenCache.expiresAt) {
      return tokenCache.token;
    }

    const { corpId, secret } = this.getConfig();
    const result = await this.request('/cgi-bin/gettoken', {
      corpid: corpId,
      corpsecret: secret,
    });
    if (result.errcode !== 0 || !result.access_token || !result.expires_in) {
      this.ctx.logger.warn('[wecom] gettoken rejected: %s', result.errcode);
      throw unavailable();
    }

    tokenCache = {
      token: result.access_token,
      expiresAt: Date.now() + (result.expires_in - 60) * 1000,
    };
    return tokenCache.token;
  }

  public async login(code: string) {
    const { ctx } = this;
    const { corpId } = this.getConfig();
    const result = await this.request('/cgi-bin/auth/getuserinfo', {
      access_token: await this.accessToken(),
      code,
    });
    if (result.errcode !== 0) {
      this.ctx.logger.warn('[wecom] identity rejected: %s', result.errcode);
      throw new ApiError(401, 'WECOM_CODE_REJECTED', '企业微信授权失败，请重新登录');
    }
    if (!result.userid || result.userid.includes('/')) {
      throw deny('请使用本企业成员账号登录');
    }

    const session = await this.app.knex.transaction(async (trx) => {
      const identity = await trx('user_identities').where({
        provider: 'wecom',
        app_id: corpId,
        openid: result.userid,
        status: 1,
      }).first('id', 'user_id');
      if (!identity) throw deny('企业微信账号尚未绑定或绑定已停用');

      const user = await trx('users')
        .where({ id: identity.user_id, status: 1 })
        .first('id');
      if (!user) throw deny('工作台账号已停用');

      const timestamps = { last_login_at: sqlNow(), updated_at: sqlNow() };
      await trx('user_identities').where({ id: identity.id }).update(timestamps);
      await trx('users').where({ id: user.id }).update(timestamps);

      return ctx.service.session.create(
        Number(user.id), ctx, trx, { setCookie: false },
      );
    });

    setSessionCookie(ctx, session.token, this.app.config.auth.normalHours * 3_600_000);
  }
}
```

这里按当前单实例、单应用部署展示进程内缓存。线上使用时按企业微信返回的 `expires_in` 缓存 token，合并并发刷新，并在明确收到 token 失效错误时清除缓存。网络超时或身份接口返回失败时，提示用户重新发起授权，避免盲目重放一次性 `code`。多个应用各自使用独立缓存键，多实例按部署需要使用共享缓存。

示例复用 [session.ts](../backend/app/service/session.ts) 的事务参数，提交后才发送 Cookie。当前 [auth-cookie.ts](../backend/app/lib/auth-cookie.ts) 将会话 Cookie 的 `secure` 写为 `false`。正式接入 HTTPS 时，需让生产环境的会话 Cookie 设置 `Secure`，并同步统一设置、清理和退出流程。授权 `state` Cookie 已要求 HTTPS，联调时也应使用 HTTPS 测试域名。

OAuth 日志保留接口名、状态和错误码。检查 Nginx 和 Egg 的访问日志与异常日志，将回调 URL 的查询串排除或脱敏，避免记录 `code`、`state`、Secret 和 `access_token`。

官方文档：[获取 access_token](https://developer.work.weixin.qq.com/document/path/91039) · [获取访问用户身份](https://developer.work.weixin.qq.com/document/path/91023)

## 5. 在登录页增加浏览器扫码入口

企业微信内直接从应用主页发起授权。需要普通浏览器扫码时，在 [frontend/src/pages/login/index.jsx](../frontend/src/pages/login/index.jsx) 的账号密码表单外加按钮，并在启用企业微信的部署中显示。浏览器需要导航到授权入口以跟随跨站跳转。

```jsx
<Button
  block
  size="large"
  onClick={() => window.location.assign('/api/wecom/scan')}
>
  企业微信扫码登录
</Button>
```

登录后，桌面端进入 `/welcome`，移动端 H5 进入 `/m/home`。两端继续通过 `/api/system/user/info.json` 加载当前用户，并按 `needModifiedPwd` 提示首次改密。企业微信扫码使用企业微信提供的授权二维码，本项目现有的手机扫码入口仍按已有一次性票据流程运行。

## 6. 联调和排查

1. 从企业微信工作台点击应用，确认回调后进入 `/m/home`，且 `/api/system/user/info.json` 返回预绑定账号。
2. 在普通浏览器点击扫码登录，用同一成员扫码，确认进入 `/welcome`，角色和权限与密码登录一致。
3. 分别使用未绑定成员、已停用绑定和已停用账号，确认都无法获得 `biz_sid`。再核验登录后首次改密和退出。
4. 修改或删除 `state`、让授权超时、重复访问同一回调地址，确认不会建立新会话。核验生产会话 Cookie 的 `Secure`、`HttpOnly` 和 `SameSite=Lax` 属性。
5. 自动化测试可模拟企业微信的 token 和身份接口，覆盖 `userid`、仅返回 `openid`、上游失败和账号状态。完成代码接入后运行后端和前端检查。

```bash
cd backend
npm test

cd ../frontend
npm run build
```

| 现象 | 检查项 |
| --- | --- |
| 企业微信返回 `50001` | 核对 `redirect_uri` 的域名与生成 access_token 的自建应用配置是否一致 |
| 身份接口只返回 `openid` | 确认扫码或打开应用的人属于配置中的企业 |
| 回调提示授权状态失效 | 检查是否从同一个浏览器和域名开始授权，HTTPS、Cookie、代理协议头及 `APP_KEYS` 是否正确，或是否已被新授权覆盖 |
| 手动访问回调看到 404 | 检查 `/api/` 转发、Egg 路由和实际部署版本 |
| 应用在企业微信工作台里不可见 | 查看测试成员是否在应用可见范围内 |
| 能拿到身份但工作台拒绝登录 | 对照返回的 `userid`、CorpID、本地账号状态和 `user_identities` 绑定记录 |

## 7. 按需接入应用消息和事件

### 发送应用消息

在后端复用应用的 access_token 缓存，向 `https://qyapi.weixin.qq.com/cgi-bin/message/send` 发 POST 请求，并在查询参数传 `access_token`。按响应的 `errcode` 和无效接收者字段判断发送结果。AgentID 以数字传递，测试收件人使用应用可见范围内的企业微信 UserID。

```json
{
  "touser": "zhangsan",
  "msgtype": "markdown",
  "agentid": 1000002,
  "markdown": {
    "content": "## 业务提醒\n> 有一条业务待处理，请打开工作台查看。"
  }
}
```

官方文档：[发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)

### 接收应用事件

需要订阅消息或应用事件时，在企业微信后台配置「接收消息服务器」，使用独立的 URL，例如 `/api/wecom/events`，以及 Token 和 EncodingAESKey。

1. 保存配置时，企业微信先发 GET 请求。用 Token、`timestamp`、`nonce` 和加密的 `echostr` 校验 `msg_signature`，成功后返回解密后的 `echostr` 明文。
2. 实际推送走 POST。服务读取 XML 中的 `Encrypt`，按官方方案校验签名、解密并验证接收方标识，再解析事件。优先使用官方加解密示例，按事件文档的要求应答，并对重试投递做幂等处理。
3. 现有 `originGuard` 对 POST 校验 JSON 和浏览器来源。接入 XML 推送时，仅对事件回调的确切路径和方法配置例外，并让该路由在执行任何业务操作前完成签名和接收方校验。事件回调和 OAuth 登录回调使用各自的路径与校验。

官方文档：[回调配置](https://developer.work.weixin.qq.com/document/path/90930) · [加解密方案](https://developer.work.weixin.qq.com/document/path/90968)
