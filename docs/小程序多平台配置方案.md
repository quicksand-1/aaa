# 小程序多平台配置方案

## 1. 当前项目状态

当前项目位于 `miniapp/`，使用 Taro 4.3.3、React 和 TypeScript。

现有配置具备以下特点：

- 依赖中只有 `@tarojs/plugin-platform-weapp`
- `package.json` 只有微信小程序的构建和开发命令
- `project.config.json` 是微信开发者工具配置
- `project.config.json` 中固定了微信 AppID
- `.env.development`、`.env.production` 和 `.env.test` 已经预留 `TARO_APP_ID`
- `src/config.ts` 已经通过 `TARO_APP_API_BASE` 读取接口地址
- `types/global.d.ts` 已经声明了 `TARO_ENV` 和 `TARO_APP_ID`

这里需要区分两种场景。

- 同一个平台使用不同的开发、测试和生产 AppID
- 同一套代码编译到微信、支付宝、抖音、百度、QQ 或京东等不同平台

第一种场景主要依赖环境变量。第二种场景还需要平台编译插件和平台项目配置。

## 2. 推荐目录结构

建议保留微信配置，同时按实际接入的平台增加配置文件和环境文件。

```text
miniapp/
├── project.config.json
├── project.tt.json
├── project.swan.json
├── .env.weapp-development
├── .env.weapp-production
├── .env.alipay-development
├── .env.alipay-production
├── .env.tt-development
└── .env.tt-production
```

`project.config.json` 继续作为微信开发者工具配置。

抖音、百度等平台可以使用对应的 `project.*.json` 配置文件。支付宝、QQ、京东使用对应 Taro 平台插件约定的配置文件名。项目配置文件应从对应平台开发者工具导出，或基于平台模板维护，避免把微信配置字段直接复制到其他平台。

## 3. 安装平台插件

只安装实际需要的平台插件。版本与当前 Taro 版本保持一致。

例如增加支付宝和抖音平台：

```bash
cd miniapp

npm install -D \
  @tarojs/plugin-platform-alipay@4.3.3 \
  @tarojs/plugin-platform-tt@4.3.3
```

其他常见平台插件包括：

```text
@tarojs/plugin-platform-swan
@tarojs/plugin-platform-qq
@tarojs/plugin-platform-jd
@tarojs/plugin-platform-h5
```

不需要一次性安装所有平台插件。每增加一个平台，都应同步确认该平台的组件、API 和项目配置要求。

## 4. 增加构建命令

建议保留现有命令，并为新增平台增加对应的构建和开发命令。

```json
{
  "scripts": {
    "build:weapp": "taro build --type weapp",
    "dev:weapp": "taro build --type weapp --watch",

    "build:alipay": "taro build --type alipay",
    "dev:alipay": "taro build --type alipay --watch",

    "build:tt": "taro build --type tt",
    "dev:tt": "taro build --type tt --watch"
  }
}
```

`--type` 决定目标平台。常见值包括：

```text
weapp / swan / alipay / tt / qq / jd / h5 / rn
```

## 5. 使用环境文件管理 AppID 和接口地址

建议使用 `--mode` 区分平台和运行环境。

开发环境文件示例：

```dotenv
# .env.weapp-development
TARO_APP_ID=wx开发环境AppID
TARO_APP_API_BASE=http://127.0.0.1:7001/api
```

```dotenv
# .env.alipay-development
TARO_APP_ID=支付宝开发环境AppID
TARO_APP_API_BASE=http://127.0.0.1:7001/api
```

生产环境文件示例：

```dotenv
# .env.weapp-production
TARO_APP_ID=wx生产环境AppID
TARO_APP_API_BASE=https://example.com/api
```

```dotenv
# .env.alipay-production
TARO_APP_ID=支付宝生产环境AppID
TARO_APP_API_BASE=https://example.com/api
```

构建命令可以明确指定模式：

```json
{
  "scripts": {
    "dev:weapp": "taro build --type weapp --mode weapp-development --watch",
    "build:weapp": "taro build --type weapp --mode weapp-production",

    "dev:alipay": "taro build --type alipay --mode alipay-development --watch",
    "build:alipay": "taro build --type alipay --mode alipay-production"
  }
}
```

当前 Taro 的项目配置生成逻辑会优先读取 `TARO_APP_ID`，并把它写入生成目录中的项目配置。因此不应手动编辑 `dist/project.config.json` 来切换环境 AppID。

当前已有的 `.env.development` 和 `.env.production` 可以继续作为默认环境文件。引入平台专用模式后，建议在构建脚本中显式指定 `--mode`，减少误用环境配置的可能。

## 6. 配置文件中的平台差异

公共配置继续放在 `config/index.ts`。

当前的接口地址定义可以继续保留：

```ts
defineConstants: {
  'process.env.TARO_APP_API_BASE': JSON.stringify(
    process.env.TARO_APP_API_BASE || 'http://127.0.0.1:7001/api'
  )
}
```

应用配置需要区分平台时，可以读取 `process.env.TARO_ENV`：

```ts
const platformTitle = {
  weapp: '业务工作台',
  alipay: '业务工作台',
  tt: '业务工作台'
} as const

const platform = process.env.TARO_ENV as keyof typeof platformTitle

export default defineAppConfig({
  pages: [
    'pages/index/index',
    'pages/login/index',
    'pages/home/index',
    'pages/modules/index',
    'pages/profile/index',
    'pages/password/index',
    'pages/chat/index'
  ],
  window: {
    navigationBarTitleText: platformTitle[platform] || '业务工作台',
    navigationBarBackgroundColor: '#fff',
    navigationBarTextStyle: 'black',
    navigationStyle: 'custom'
  }
})
```

平台 API 有差异时，再在具体 service 或组件中使用 `process.env.TARO_ENV` 做局部适配。公共页面和服务代码继续使用 Taro 统一 API。

## 7. 构建产物目录

如果每次只构建一个平台，可以继续使用当前配置：

```ts
outputRoot: 'dist'
```

如果需要同时保留多个平台的产物，可以根据目标平台隔离输出目录：

```ts
outputRoot: `dist/${process.env.TARO_ENV || 'weapp'}`
```

产物目录会变成：

```text
dist/
├── weapp/
├── alipay/
└── tt/
```

此时各平台开发者工具分别打开对应目录。

需要注意，根目录的 `project.config.json` 是源码配置，构建生成的项目配置位于各自产物目录中。不要直接修改 `dist` 中的生成文件。

## 8. 推荐落地顺序

建议按以下顺序推进：

1. 明确第一批需要支持的平台和每个平台的开发、测试、生产 AppID。
2. 安装对应的 Taro 平台插件。
3. 增加平台构建和开发命令。
4. 建立平台和环境对应的 `.env.*` 文件。
5. 为需要在开发者工具中打开的平台准备对应项目配置文件。
6. 先验证公共页面、登录、请求和本地存储能力。
7. 再处理平台专属 API、支付、订阅、分享或登录能力。
8. 如果需要并行保留构建结果，再启用按平台隔离的 `outputRoot`。

## 9. 针对当前仓库的最小改造

当前仓库最适合先完成以下改造：

- 保留 `miniapp/project.config.json` 作为微信配置
- 添加实际需要的平台插件，不一次性安装全部插件
- 为每个平台增加 `build` 和 `dev` 命令
- 使用 `.env.<platform>-<environment>` 管理 AppID 和接口地址
- 继续复用 `src/config.ts` 的接口地址读取方式
- 只有存在真实平台差异时，才在 `app.config.ts` 或业务代码中读取 `TARO_ENV`
- 暂时按平台逐个构建，确认流程稳定后再考虑隔离多个输出目录
