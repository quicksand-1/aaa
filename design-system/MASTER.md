# 业务工作台设计系统

> **定位：** 本项目所有 Web、H5 和小程序界面的全局设计基线。
>
> **使用顺序：** 先读取 `design-system/pages/<page>.md`；存在时，其页面级规则覆盖本文件；不存在时，严格遵守本文件。
>
> **维护原则：** 本文件定义目标规范，不要求为了统一而批量重构无关页面。修改页面时，只需让被修改区域符合规范；发现系统性偏差时再单独处理全局主题。

- **项目：** 业务工作台 / 通用业务管理平台
- **技术栈：** Umi/Max 4、React 18、Ant Design 6、Pro Components、TailwindCSS 3
- **产品形态：** 企业级中后台、移动端 H5、多端小程序
- **更新时间：** 2026-11-24

---

## 1. 产品目标

这是面向企业内部人员的业务工作台，不是营销官网。界面首先要帮助用户快速找到入口、理解状态、完成操作，其次才是表达品牌个性。

设计需要同时满足：

1. **高效：** 信息密度合理，路径短，操作反馈明确。
2. **可信：** 权限、状态、危险操作和系统结果清晰可见。
3. **一致：** 同类信息、操作和页面结构使用相同模式。
4. **克制：** 用层级、留白、边框和少量品牌色建立秩序，不依赖装饰堆叠。
5. **可扩展：** 新业务模块可以复用现有令牌和组件，而不是另起一套视觉语言。

## 2. 视觉方向

### 2.1 风格定义

**Data-Dense Swiss Enterprise + Trust & Authority**

- 以 Swiss Modernism 的网格、留白、清晰排版和单一主色为基础。
- 借鉴数据密集管理后台的高信息效率，但不牺牲可读性和触控尺寸。
- 通过稳定的导航、明确的状态色和高对比文本建立信任感。
- 保留现有品牌蓝和中性灰体系，不引入金色、紫色渐变或营销落地页视觉。

### 2.2 视觉性格

- 平静、专业、直接。
- 平面优先、边框优先、阴影克制。
- 蓝色只用于主操作、当前状态和关键数据，不大面积铺色。
- 中文正文优先保证行高和对比度，不追求过度紧缩。
- 桌面端偏紧凑，移动端偏易触达。

### 2.3 决策记录

UI/UX 技能初始推荐了“Enterprise Gateway”营销页模式、金色主色和紫色 CTA。该方案与本项目的登录后工作台场景不匹配，因此采用如下调整：

| 初始建议                      | 本项目决策                                               |
| ----------------------------- | -------------------------------------------------------- |
| 金色主色 + 紫色 CTA           | 保留既有 Ant Design 蓝色 `#1677ff`，紫色不用于品牌和 CTA |
| Hero、客户 Logo、销售转化区块 | 不适用于内部工作台；使用任务入口、状态概览和数据模块     |
| IBM Plex Sans                 | 沿用现有 Inter + 中文系统字体栈                          |
| 深色主背景                    | 默认浅色工作台；深色仅用于侧边导航                       |
| 大圆角营销卡片                | 桌面控制保持紧凑圆角，移动端按触控场景使用较大圆角       |

## 3. 设计令牌

### 3.1 品牌色

与 `frontend/tailwind.config.js` 保持一致。

| Token       | Hex       | 主要用途                     |
| ----------- | --------- | ---------------------------- |
| `brand-50`  | `#e6f4ff` | 选中背景、浅色提示           |
| `brand-100` | `#bae0ff` | 浅色边框、信息背景           |
| `brand-200` | `#91caff` | 次要强调                     |
| `brand-300` | `#69b1ff` | 图表辅助色                   |
| `brand-400` | `#4096ff` | hover、次级强调              |
| `brand-500` | `#1677ff` | 品牌主色、主按钮、当前导航   |
| `brand-600` | `#0958d9` | 链接文字、小字号强调、active |
| `brand-700` | `#003eb3` | 高对比强调                   |
| `brand-800` | `#002c8c` | 稀有深色强调                 |
| `brand-900` | `#001d66` | 稀有深色强调                 |
| `brand-950` | `#001529` | 桌面侧边导航背景             |

规则：

- 新业务代码优先使用 `brand-*`，不要继续新增 `blue-*` 色阶。
- 小字号文本或文字链接需要足够对比度时使用 `brand-600` 或更深色。
- 一个页面只保留一个主操作视觉焦点；主色面积不宜超过内容区域的 10%。

| 角色                     | Hex                         |
| ------------------------ | --------------------------- |
| Sider background         | `#001529`                   |
| Header title             | `#ffffff`                   |
| Menu text                | `rgba(255, 255, 255, 0.85)` |
| Menu hover text          | `#ffffff`                   |
| Menu hover background    | `rgba(255, 255, 255, 0.08)` |
| Menu selected background | `#1677ff`                   |
| Menu selected text       | `#ffffff`                   |

导航必须始终明确显示当前位置；不要依赖 hover 作为唯一状态提示。

### 3.4 字体

| 角色             | 字体栈                                                                            |
| ---------------- | --------------------------------------------------------------------------------- |
| Latin / Numerals | `Inter`                                                                           |
| 中文正文         | `-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif` |
| 等宽             | `"JetBrains Mono", "SFMono-Regular", Consolas, monospace`                         |

推荐完整字体栈：

```css
font-family: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
  "Microsoft YaHei", sans-serif;
```

### 3.5 字号与字重

| 层级          | 字号 / 行高     | 字重    | 用途                   |
| ------------- | --------------- | ------- | ---------------------- |
| Page title    | `24px / 32px`   | 600     | 页面主标题             |
| Section title | `20px / 28px`   | 600     | 区块标题               |
| Card title    | `16px / 24px`   | 600     | 卡片、抽屉标题         |
| Body          | `14px / 22px`   | 400     | 默认正文               |
| Body strong   | `14px / 22px`   | 500-600 | 强调正文、表格关键字段 |
| Secondary     | `13px / 20px`   | 400     | 辅助说明               |
| Caption       | `12px / 20px`   | 400     | 时间、注释、元数据     |
| Data / KPI    | `24-32px / 1.2` | 600     | 关键数字               |

规则：

- 不使用小于 `12px` 的正文。
- 中文正文不使用过度紧凑的字间距。
- `tracking-tight` 只用于英文或数字为主的页面大标题，不用于中文正文。
- 表单标签、按钮、表格内容默认 `14px`；移动端可按平台缩放比例调整，但最小视觉字号不低于 `12px`。

### 3.6 间距

基础单位为 `4px`。

| Token      | 值     | 用途                       |
| ---------- | ------ | -------------------------- |
| `space-1`  | `4px`  | 图标与短文本               |
| `space-2`  | `8px`  | 紧凑分组、标签间距         |
| `space-3`  | `12px` | 表单控件内部、卡片紧凑间距 |
| `space-4`  | `16px` | 默认网格间距               |
| `space-5`  | `20px` | 区块间距、桌面内容边距     |
| `space-6`  | `24px` | 卡片内边距、主要区块间距   |
| `space-8`  | `32px` | 页面分区                   |
| `space-10` | `40px` | 大区块                     |
| `space-12` | `48px` | 空状态、引导页             |

Tailwind 中优先使用 `gap-4`、`p-6`、`mt-6` 等标准刻度，避免无理由的 `[13px]`、`[27px]` 等任意值。

### 3.7 圆角

| 场景                     | 圆角     | 说明                                 |
| ------------------------ | -------- | ------------------------------------ |
| 桌面 Ant Design 基础控件 | `2px`    | 当前全局主题基线                     |
| 独立登录页控件、图标容器 | `8px`    | 登录页可通过局部 ConfigProvider 覆盖 |
| 桌面卡片、弹窗内容块     | `12px`   | 使用 `rounded-xl`                    |
| 移动端卡片、面板         | `16px`   | 使用 `rounded-2xl`                   |
| 头像、状态点、胶囊标签   | `9999px` | 只用于天然圆形或胶囊语义             |

不要给所有元素统一加大圆角，也不要用大圆角包装信息密度高的表格和表单。

### 3.8 阴影与层级

- 优先使用边框、背景和留白建立层级。
- 普通卡片默认无阴影或 `shadow-sm`。
- `shadow-lg`、`shadow-xl` 仅用于浮层、二维码面板、移动端独立外壳等明确脱离文档流的元素。
- 不叠加大面积阴影、模糊光晕和玻璃拟态。
- 自定义浮层层级交给 Ant Design；页面内 sticky header/nav 使用可控的 `z-index: 10-20`，不要随意使用 `9999`。

### 3.9 动效

| 类型             | 时长           | 缓动        |
| ---------------- | -------------- | ----------- |
| 颜色、边框、背景 | `150-200ms`    | ease-out    |
| 位移、展开、弹层 | `200-300ms`    | ease-in-out |
| 复杂页面过渡     | 不超过 `400ms` | ease-in-out |

规则：

- hover 不得改变元素尺寸，不使用会推动布局的 `scale`。
- 可用颜色、透明度、边框和阴影变化表达 hover。
- 必须支持 `prefers-reduced-motion`。
- 加载状态优先使用 Ant Design 的 `Spin`、`Skeleton` 和按钮 loading，不制造无意义动画。

### 3.10 响应式断点

沿用 Tailwind 默认断点：

| 名称          | 宽度          | 主要策略                 |
| ------------- | ------------- | ------------------------ |
| Mobile        | `< 640px`     | 单列、触控优先           |
| Tablet        | `640-767px`   | 可双列，仍避免复杂侧栏   |
| Small desktop | `768-1023px`  | 常用双列或紧凑表格       |
| Desktop       | `1024-1279px` | 展开侧边导航和完整工具栏 |
| Wide desktop  | `>= 1280px`   | 数据区域可使用更多列     |

关键验收宽度：`375px`、`768px`、`1024px`、`1440px`。

## 4. 页面布局

### 4.1 桌面端

- 使用 ProLayout 侧边布局，侧栏宽度默认 `180px`。
- 内容区沿用现有 `20px 22px 36px` 内边距；需要紧凑工具栏时按页面语义局部调整。
- 数据页使用可用宽度，不强制统一最大宽度。
- 说明页、空状态和引导内容可使用 `max-w-3xl` 或 `max-w-4xl`，避免长文本过宽。
- 页面左侧对齐线必须一致；不要在一个页面内混用多种内容宽度。
- 列表页结构优先级：标题与操作区 → 筛选区 → 表格 → 分页。
- 新增或编辑表单放入独立抽屉，不把复杂表单直接塞进列表页。

### 4.2 移动端 H5

- 使用独立 `MobileLayout`，最大宽度 `520px`，在桌面浏览器中居中展示。
- 顶部栏高度 `56px`，底部 Tab 高度 `64px`。
- 页面必须处理 `safe-area-inset-top` 和 `safe-area-inset-bottom`。
- 内容区独立滚动，页面主体使用 `100dvh`，避免移动浏览器地址栏导致跳动。
- 默认页面内边距 `16px`；卡片之间至少 `12-16px`。
- 可点击区域最小 `44 × 44px`。
- 表格优先横向滚动；信息简单时再切换为卡片列表，不得直接裁掉关键字段。

### 4.3 小程序

- 页面背景使用 `#f8fafc`，主文本使用 `#0f172a`，品牌色与 Web 保持一致。
- 字体使用系统中文栈，不依赖远程字体。
- 主要按钮使用 `brand-500`，次要按钮使用浅蓝背景和蓝色文字。
- 触控区域按 Taro 尺寸体系保证可点面积，视觉密度可以高于 H5，但不得缩小到难以点击。
- 空状态必须包含说明和下一步动作，不能只显示空白容器。

## 5. 组件规范

### 5.1 组件选择顺序

使用 Ant Design、Pro Components 或 `@ant-design/x` 前，先检查 Fintech 是否提供语义匹配的封装。

| 场景                 | 优先组件        | 仍使用原生组件的情况             |
| -------------------- | --------------- | -------------------------------- |
| 标准抽屉、抽屉表单   | `DrawerBox`     | 确认、警告等轻量对话使用 `Modal` |
| 链接式操作、权限操作 | `LinkBtn`       | 提交按钮或不匹配的特殊按钮       |
| 数据列表             | `ProTableAsync` | 非表格布局或封装能力不匹配       |
| 字典、异步下拉       | `SelectList`    | 高度定制的选择交互               |
| 配置式描述列表       | `DescList`      | 简单或特殊布局                   |
| 标准标签页           | `MagicTabs`     | 复杂自定义标签页                 |
| Schema 表单字段      | `FormSchema`    | 必须直接控制 `Form.Item` 的场景  |
| 动态表单列表         | `EditTable`     | 非表格形态的动态结构             |
| Markdown 内容        | `Xmarkdown`     | 普通标签和纯 JSX 文本            |

- 常规组件从 `fintech` 导入，X 系列从 `fintech/x` 导入。
- 不修改 `frontend/src/fintech`。
- 使用不熟悉的组件前先读对应文档和现有调用示例。

### 5.2 按钮

- 一个操作区域内只保留一个 `primary` 按钮。
- 次要操作使用默认按钮，危险操作使用 `danger`，不要用蓝色按钮表达删除。
- 纯图标按钮必须提供 `aria-label` 和 Tooltip。
- 图标统一使用 `@ant-design/icons` 或现有 SVG 图标，不使用 emoji 充当 UI 图标。
- hover 使用颜色、背景或边框变化，不使用导致布局位移的缩放。
- 提交或异步操作必须显示 loading，禁止重复点击。

### 5.3 表单

- 标签始终可见，不能只用 placeholder 充当标签。
- 必填项、帮助说明和错误信息应靠近对应字段。
- 表单采用纵向布局，复杂表单按业务分组，不把多个无关字段挤在同一行。
- 错误信息说明“哪里错、如何改”，不只显示“格式错误”。
- 禁用态与只读态必须可区分；只读用于展示可复制的已确定值。
- 表单提交成功后关闭抽屉并刷新相关列表；失败时保留用户输入。

### 5.4 抽屉与弹窗

- 新增、编辑、详情抽屉默认宽度 `480px`；复杂表单可使用 `640px`。
- 移动端抽屉使用全宽，并保留安全区内边距。
- 轻量确认使用 `Modal`，复杂编辑使用 `DrawerBox`，不要互相替代。
- 破坏性操作必须在操作名称、提示文案和按钮颜色上同时表达风险。
- 关闭含未保存内容的表单前必须提示，除非表单明确为即时保存模式。

### 5.5 表格

- 表头、排序、筛选和分页使用项目现有 Pro Components 模式。
- 默认行高保持可读；紧凑模式不低于 `40px`，移动端触控行不低于 `44px`。
- 数字右对齐，文本左对齐，状态居中或左对齐并配文本标签。
- 长文本提供省略与查看详情入口，不挤压其他关键列。
- 批量操作在选中后出现，并明确显示选中数量和可执行动作。
- 无数据时使用可理解的空状态和下一步操作，不留空白表格。

### 5.6 状态反馈

| 场景         | 方式                               |
| ------------ | ---------------------------------- |
| 页面初次加载 | Skeleton 或区域 loading            |
| 按钮提交     | Button loading + 禁用重复提交      |
| 短暂成功     | `message.success`                  |
| 需要持续说明 | 页面内 Alert                       |
| 字段错误     | Form Item 校验信息                 |
| 空数据       | 空状态 + 说明 + 操作入口           |
| 无权限       | 明确说明权限缺失，不伪装成系统错误 |
| 会话失效     | 统一跳转登录，不在每个页面重复实现 |

全局错误处理已经位于 `frontend/src/app.tsx`。仅为通用错误提示时，不要在业务页面重复 `.catch()`；需要降级、回滚、清理或重试时再做局部处理。

### 5.7 导航

- 桌面端当前菜单必须有高亮背景和白色文字。
- H5 当前 Tab 使用 `brand-600`，非当前项使用中性灰。
- 页面标题与导航名称保持语义一致。
- 可分享或可恢复的视图状态应进入 URL，不只保存在组件内部。
- 返回按钮用于移动端非 Tab 页面；必须有 `aria-label`。

### 5.8 卡片与容器

- 卡片用于承载一个完整信息单元，不用于给每个字段套框。
- 卡片内不再嵌套无意义卡片；需要分组时优先使用标题、分隔线和留白。
- 卡片标题优先描述业务对象，不使用泛化的“信息”“内容”。
- 可点击卡片必须有 hover 反馈、`cursor-pointer` 和键盘可达性。
- 普通卡片默认白底、浅边框、无重阴影。

### 5.9 图表

- 图表必须服务明确问题，不为装饰而添加。
- 折线用于趋势，柱状用于比较，漏斗用于阶段转化，饼图只用于少量清晰分类。
- 使用品牌蓝作为主系列，状态色作为语义系列，紫色仅作为分类辅助色。
- 坐标轴、图例、单位和空状态必须完整。
- 不使用 3D、旋转、发光或高饱和渐变。
- 手机端减少图例和坐标密度，但不得隐藏单位或关键数据。

### 5.10 对话类界面

- 消息层级清晰区分用户、助手和系统状态。
- 发送区、停止生成、重试和错误恢复必须有明确状态。
- 流式输出时避免整页跳动，保持滚动位置可预期。
- Markdown 内容使用项目 `Xmarkdown` 或现有 X 系列组件，不另建渲染器。

---

## 6. 文案规范

- 使用简洁、直接的中文，优先动词开头：`新增账户`、`保存修改`、`导出数据`。
- 同一动作在不同页面使用同一名称：`新增` 不混用 `创建`、`添加`；`删除` 不混用 `移除`。
- 标题说明对象和目的，不使用空泛口号。
- 错误文案说明原因和下一步，不暴露内部堆栈或实现细节。
- 空状态文案包含“当前没有什么”和“可以做什么”。
- 时间、数量、金额、权限等关键数据必须标明单位或范围。
- 面向内部用户时避免营销话术、夸张形容词和无意义感叹号。

---

## 7. 无障碍要求

- 目标达到 WCAG 2.2 AA。
- 所有表单控件有关联标签；所有图片有有效 `alt`，装饰图片使用 `alt=""`。
- 键盘可访问所有交互，Tab 顺序与视觉顺序一致。
- 焦点状态可见，不通过 `outline: none` 移除焦点。
- 颜色不能作为唯一状态指示，必须辅以文字、图标或形状。
- 正文对比度不低于 `4.5:1`，大号文本不低于 `3:1`。
- 页面只使用一个 `h1`，标题层级必须连续。
- 动态错误和异步结果使用适当的 `aria-live` 或组件内置无障碍能力。
- 弹窗和抽屉需要焦点管理，关闭后焦点返回触发元素。
- 尊重 `prefers-reduced-motion`。

## 8. 工程实现约定

### 8.1 Tailwind

- `frontend/src/components`、`frontend/src/pages`、`frontend/src/layouts` 优先使用 TailwindCSS。
- 复用 `tailwind.config.js` 中已有 `brand`、`slate`、字体和圆角刻度。
- 新代码优先使用 `text-slate-900`、`text-slate-600`、`border-slate-200`、`bg-slate-50` 等标准组合。
- 避免新增一次性色值；确需新增且会被复用时，先更新 Tailwind 令牌和本文件。
- 复杂第三方覆盖、伪元素和无法清晰表达的状态可以沿用项目现有样式方案。

### 8.2 Ant Design

- 全局主题位于 `frontend/.umirc.ts`，当前基础圆角为 `2px`。
- 登录页等独立场景可使用局部 `ConfigProvider`，但必须复用本文件的品牌色、语义色和字体。
- 新页面不要随意覆盖 Ant Design 内部类名；优先使用组件 token、语义结构和 Tailwind 外层布局。
- 修改全局主题前先确认影响桌面端、H5、弹窗、表格和表单，不做单页面驱动的大范围覆盖。

### 8.3 响应式实现

- 优先使用 Tailwind 断点，不用 JavaScript 判断窗口宽度来切换布局。
- 表格必须放在可滚动或响应式容器中，禁止撑破页面宽度。
- 固定头部和底部导航必须预留内容空间。
- 移动端优先保证点击、滚动和安全区，不为了塞入更多信息而缩小字体。

### 8.4 代码边界

- 不修改 `frontend/src/fintech`。
- 不引入新的全局状态库。
- 不新增第三方 UI 库、图标库或动画库，除非现有依赖无法满足需求。
- 页面业务请求遵循 `import { request } from 'fintech'`。
- 组件拆分以独立职责为依据，不以减少行数为目标。

## 9. 页面级覆盖

页面存在特殊业务语境时，在 `design-system/pages/<page-name>.md` 中记录覆盖规则。

推荐格式：

```md
# <页面名称> 设计覆盖

- 对应路由：`/<route>`
- 覆盖原因：<业务或交互原因>
- 继承：除以下条目外，全部继承 `design-system/MASTER.md`

## 例外

1. <具体令牌或组件规则>
2. <适用范围和禁止事项>
```

规则：

- 页面覆盖只写差异，不复制 Master。
- 覆盖必须有明确原因和适用范围。
- 不允许用页面覆盖规避通用无障碍、权限和危险操作规范。
- 页面设计变化稳定后，应判断是否应回流到 Master，而不是长期保留私有规则。

## 10. 禁止模式

- 不把内部工作台做成营销落地页：不使用 Hero、客户 Logo 墙、销售 CTA、行业切换等官网结构。
- 不使用金色主色、紫色 CTA、AI 紫粉渐变或装饰性光晕。
- 不使用 emoji 作为 UI 图标。
- 不使用玻璃拟态、重度模糊和大面积透明卡片。
- 不使用大面积渐变背景替代信息层级。
- 不把大圆角、阴影和动画同时堆叠到普通业务卡片。
- 不使用小于 `12px` 的正文或低对比灰色正文。
- 不用颜色单独表达成功、警告、错误或选中状态。
- 不让 hover 改变布局尺寸。
- 不隐藏关键字段来强行适配移动端。
- 不新增一次性颜色、字体、间距或阴影令牌。
- 不在每个页面重复处理全局请求错误和会话失效。
- 不通过覆盖 Ant Design 内部类名实现本可由 token 或布局解决的问题。

## 11. 交付前检查

### 视觉

- [ ] 页面只有一个明确主操作。
- [ ] 标题、正文、辅助文字层级清晰。
- [ ] 颜色、圆角、阴影和间距来自既有令牌。
- [ ] 普通卡片没有依赖过重阴影或装饰性渐变。
- [ ] 图标来自统一图标库，没有 emoji 图标。

### 交互

- [ ] 所有可点击元素有 hover、focus 和 disabled 状态。
- [ ] 可点击元素使用 `cursor-pointer`，原生按钮语义正确。
- [ ] 异步操作有 loading，且不会重复提交。
- [ ] 空状态、错误态、无权限态都有明确说明和下一步。
- [ ] 危险操作在文案和视觉上同时表达风险。

### 响应式

- [ ] 在 `375px`、`768px`、`1024px`、`1440px` 下无横向溢出。
- [ ] 移动端触控目标不小于 `44 × 44px`。
- [ ] 固定导航不遮挡内容，安全区已处理。
- [ ] 表格在窄屏可滚动或合理切换布局。
- [ ] 长文本、长数字和异常值不会撑破容器。

### 无障碍

- [ ] 正文对比度达到 `4.5:1`。
- [ ] 键盘可完成主要流程，焦点清晰。
- [ ] 表单控件均有标签，错误信息与字段关联。
- [ ] 图片有有效替代文本，装饰图片为 `alt=""`。
- [ ] 状态不只依赖颜色。
- [ ] 尊重 `prefers-reduced-motion`。

### 工程一致性

- [ ] 优先使用 Fintech 既有封装。
- [ ] 请求和权限处理沿用项目现有模式。
- [ ] 未新增不必要的依赖。
- [ ] 未修改 `frontend/src/fintech`。
- [ ] 已执行与改动风险匹配的 lint、类型检查或构建。
